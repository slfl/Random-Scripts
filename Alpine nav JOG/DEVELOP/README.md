# Реверс-инжиниринг JOG / навигации — выжимка

Краткий итог по декомпиляции прошивки, разбору дампов, захватам с линии и даташиту.
Сгруппировано по использованным файлам/источникам.

---

## 1. `SMGA.bin` — прошивка навигатора (SH-4, WinCE)

Содержимое: PE-DLL под SH-4 + кусты реестра WinCE.
Разобрано при помощи DumpNavi.

**Файлы и находки:**

- **`hardkey.dll`** — драйвер аппаратных клавиш (то, что обрабатывает пульт):
  - загружает `avcbus.dll`;
  - открывает устройство **`HKY1:`**;
  - читает данные через **`AVCtrl_ReadData`**;
  - регистрирует **6-байтовый идентификатор устройства**; в `.data` по умолчанию
    `06 31 41 34 4B 42` = `0x06` + ASCII **«1A4KB»**;
  - карту клавиш берёт из реестра **`Drivers\BuiltIn\Hardkey\KeyAssign`**
    (перечисление `RegEnumValue` в рантайме, не зашита в код).

- **`avcbus.dll`** — драйвер шины AVCLib:
  - валидатор кадра **`sub_36035dc`**: проверяет `frame[0]==0x01` (SOF),
    `frame[2]==LEN`, `frame[3]==Σpayload`;
  - **ВАЖНО:** это **другой путь шины**, НЕ протокол JOG. Формат `01 ID LEN CKS`
    к пульту отношения не имеет (см. п.3 — на проводе совсем другой кадр).

- **`SCIF.dll`** — драйвер последовательного контроллера SH-4 (SCIF/UART).
- **`coredll.dll`** — ядро WinCE (служебная, для разрешения импортов).
- **Кусты реестра** `default.hv` / `user.hv` / `boot.hv` — содержат привязку клавиш
  `Hardkey\KeyAssign` и настройки драйверов.

**Вывод по прошивке:** идентификаторы и формат `01 ID LEN` в прошивке **не совпадают**
с тем, что реально идёт по проводу от пульта. Значит JOG использует **простой
4-байтовый протокол** (см. п.3), а `avcbus`-валидатор — отдельная ветка шины.

## 3. Захваты линии данных (Saleae, логический анализатор)

Многократные экспорты фронтов с линии JOG, декодированы собственным Python-скриптом.

**Найдено (подтверждено на разных захватах):**

- линия: покой **LOW**, **инвертированная**, **LSB-first**, **8N1**;
- бит **≈208 мкс → 4800 бод** (53/53 кадра валидны при 208);
- кадр — **4 байта `[type][lo][hi][cks]`**, где `(type+lo+hi+cks)&0xFF == 0xFF`;
- `type`: `0x80` = кнопки, `0x81` = энкодер CW, `0xFF` = энкодер CCW;
- полная карта кнопок (маски `lo`/`hi`), диагонали джойстика = OR битов в `hi`;
- **RELEASE `80 00 00 7F`** — только после направлений джойстика; прочие кнопки и
  энкодер отпускание не шлют.

**Исправленная ошибка:** ранний декод на **224 мкс** давал ложный 6-байтовый кадр
`01 ID LEN CKS` (совпал с `avcbus`-форматом по случайности). Это был **неверный
бит-тайм** — истинный протокол подтверждён на 208 мкс/4800 бод.

## 4. `TMP87C447UG.pdf` — даташит микроконтроллера пульта

Найден и идентифицирован чип пульта по маркировке.

**Чип:** **Toshiba TMP87C447UG**, семейство **TLCS-870**, 8-бит CMOS, корпус LQFP-44.

**Находки из даташита:**

- простой 8-битный MCU — по сути **сканер кнопок с последовательным выходом**;
- есть **SIO** (клокируемый serial: `SI`=P74/нога44, `SO`=P75/нога43, `SCK`=P73/нога1)
  — это и есть «площадки для прошивки», что нашлись на плате;
- есть **HSO** (высокоскоростной serial-выход) + `HSCK`;
- оба аппаратных serial-блока **клокируемые** (нужны 2 линии), а у разъёма к
  навигатору **одна сигнальная линия** → связь идёт **однопроводным асинхронным
  UART** (программно «выбит» на GPIO через транзистор);
- ПЗУ — **масочное** (зашито на заводе), **электрически не читается** → дамп
  прошивки пульта недоступен без вскрытия кристалла.

**Вывод:** скрытого протокола/хендшейка в чипе нет — он шлёт ровно тот UART, что
снят на проводе (п.3).

## 5. Разбор платы пульта (аппаратный реверс, не файл)

Прозвонка и замеры на разобранном пульте.

**Найдено:**

- линия данных идёт в МК **через NPN-транзистор** (SOT23): база ← МК, эмиттер → GND,
  коллектор → линия навигатора (**открытый коллектор**);
- **базовый резистор 10 кОм**;
- напряжения: база в покое ≈ **0.77 В** (Vbe, транзистор открыт → линия LOW),
  при нажатии база переключается; линия в покое ≈ **0 В**, без пульта ≈ **3.3 В**;
- транзистор **инвертирует**: МК шлёт обычный UART, на линии получается
  инвертированный (покой LOW) — что и совпало с декодом из п.3;
- два штатных пульта работают на линии **параллельно** → «ноль» в покое **мягкий**
  (через транзистор), а не жёсткое замыкание на землю.

---

## Итоговая картина

- **Протокол пульта:** 4800 бод, 8N1, LSB, инвертированный, кадр `[type][lo][hi][cks]`
  с суммой `0xFF`. Подтверждён на проводе.
- **Выходной каскад:** NPN с открытым коллектором, база через 10 кОм — повторён в
  эмуляторе.
- **Прошивка навигатора:** клавиши обрабатывает `hardkey.dll` (через `HKY1:` /
  `AVCtrl_ReadData`); формат `01 ID LEN` в `avcbus.dll` — отдельная шина, не JOG.
- **MCU пульта:** TMP87C447 (TLCS-870), масочный ROM — дамп недоступен; скрытого
  протокола нет.

Реверс и анализ: **SLFL**.
